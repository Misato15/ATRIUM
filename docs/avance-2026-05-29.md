# Avance de portafolio e interacciones

## Objetivo del avance

El objetivo de este avance fue acercar Atrium a una experiencia tipo Behance:
las obras ya no son solo tarjetas estaticas, ahora se pueden abrir en una pagina
individual y tienen interacciones basicas de vistas y me gusta.

## Que se implemento

1. Se agregaron contadores a las obras:
   - `viewCount`: cantidad de veces que se abre una obra.
   - `likeCount`: cantidad de me gusta recibidos.

2. Se agrego la pagina publica de detalle de obra:
   - Ruta frontend: `/portfolio/:id`
   - Endpoint backend: `GET /portfolio/:id`

3. Se hizo que las tarjetas de portafolio sean clickeables.

4. Se agrego el endpoint:
   - `POST /portfolio/:id/like`

5. Se mejoro el sistema de likes para que dependa del usuario autenticado:
   - un usuario puede dar me gusta solo una vez por obra
   - si vuelve a presionar el boton, se quita el me gusta
   - la base de datos evita duplicados con una restriccion unica

6. Se actualizo la interfaz para mostrar:
   - imagen grande de la obra
   - titulo
   - descripcion
   - artista
   - categoria
   - vistas
   - me gusta

## Archivos principales modificados

### Backend

`backend/prisma/schema.prisma`

Se agregaron los campos `viewCount` y `likeCount` al modelo `PortfolioItem`.
Esto permite guardar interacciones reales en MySQL.

Tambien se agrego el modelo `PortfolioLike`, que conecta usuarios con obras.
La restriccion `@@unique([userId, portfolioItemId])` evita que el mismo usuario
pueda dar me gusta dos veces a la misma obra.

`backend/src/portfolio/portfolio.service.ts`

Aqui esta la logica de negocio:

- `findOne(id)` busca una obra especifica e incrementa `viewCount`.
- `getLikeStatus(id, userId)` revisa si el usuario actual ya dio me gusta.
- `toggleLike(id, userId)` crea o elimina el like del usuario actual.
- `createForUser(...)` sigue creando obras para el artista autenticado.

`backend/src/portfolio/portfolio.controller.ts`

Aqui se exponen las rutas HTTP:

- `GET /portfolio`
- `GET /portfolio/:id`
- `GET /portfolio/:id/like-status`
- `POST /portfolio/:id/like`
- `POST /portfolio`

### Frontend

`frontend/src/components/PortfolioItemCard.jsx`

La tarjeta ahora:

- muestra imagen usando `thumbnailUrl` o `mediaUrl`
- muestra vistas y me gusta
- funciona como link hacia `/portfolio/:id`

`frontend/src/pages/PortfolioDetailPage.jsx`

Nueva pagina para ver una obra completa. Tambien permite dar me gusta.

`frontend/src/pages/HomePage.jsx`

Ahora pasa `id`, `viewCount` y `likeCount` a cada tarjeta de obra.

`frontend/src/pages/ArtistDetailPage.jsx`

El perfil publico del artista tambien muestra tarjetas clickeables con conteos.

`frontend/src/pages/DashboardPage.jsx`

El dashboard muestra las obras propias con sus vistas y me gusta.

## Como explicar el flujo

Cuando un usuario abre una obra desde la home, React lo manda a:

```txt
/portfolio/:id
```

Esa pagina llama al backend:

```txt
GET /portfolio/:id
```

El backend busca la obra en MySQL usando Prisma y aumenta `viewCount` en 1.

Cuando el usuario presiona "Me gusta", React llama:

```txt
POST /portfolio/:id/like
```

El backend aumenta `likeCount` en 1 y devuelve la obra actualizada.

## Como demostrarlo

1. Abrir la home.
2. Hacer click en una obra.
3. Ver que abre una pagina individual de obra.
4. Refrescar o abrir de nuevo la obra para ver que suben las vistas.
5. Iniciar sesion y presionar "Me gusta" para ver que sube el contador.
6. Presionar otra vez para quitar el me gusta y ver que baja el contador.
7. Volver a la home o dashboard y revisar que las tarjetas muestran los conteos.

## Por que este avance importa

Este avance demuestra que Atrium ya no solo guarda y lista contenido.
Ahora empieza a comportarse como una plataforma multimedia real:

- los usuarios pueden explorar obras
- las obras tienen pagina propia
- el sistema registra interacciones
- el artista puede ver actividad en su contenido

Esto conecta directamente con el alcance original del proyecto: perfiles,
portafolio multimedia e interaccion mediante likes y vistas.

## Avance adicional: perfil publico del artista

Se agrego la edicion del perfil publico desde el dashboard.

El artista puede actualizar:
- nombre completo
- nombre artistico
- biografia
- ubicacion
- foto de perfil
- imagen de portada

La ruta protegida `PATCH /artists/me` usa el token JWT para identificar al usuario actual. Esto evita que un artista pueda editar perfiles de otros usuarios.

La pagina publica del artista ahora muestra una estructura visual con portada, avatar, categoria, ubicacion y portafolio.
